# М13. Рост: план встретился с реальностью

**Место в нити:** последний модуль. Вход — запущенный план с порогом пересмотра из секции 8 brief (М12), дерево (М11), данные минимум за 4 недели. До сих пор курс был про привлечение; М13 — вторая половина: рост из тех, кто уже пришёл. Дуга замыкается: сигналы после запуска возвращаются в М1 новыми интервью, в М4 — строчками журнала, в М5 — поправленным позиционированием. GTM — петля, PMM её удерживает.

## Позиция курса: первая версия плана — первая гипотеза

GTM без финиша: запустили → данные → скорректировали → снова. План расходится с реальностью по трём структурным причинам, виноватых нет:
1. **Клиент говорит одно, делает другое.** Интервью меряют намерение, рынок — действие; расхождение — рабочие данные. Триалы приходят, но не активируются — смотри онбординг и точку слома М3, понимание клиента ни при чём.
2. **Рынок изменился между планом и запуском** (конкурент, регулятор, бюджеты). Для этого журнал сигналов М4: значимое изменение — пересмотр конкретного узла, остальные не трогаются.
3. **Внутренние ограничения проявились позже.** Из пяти рычагов ресурсов хватило на два — норма: одновременно живут 2–3 рычага; PMM с двумя работающими и одним в резерве устойчивее пяти недоведённых.

GTM-план — живой документ: итерация, не пересборка с нуля. PMM, читающий расхождение как провал, ищет виноватых; читающий как данные — смотрит, где тяга, и двигает ресурсы туда.

## Три сигнала (сначала тип, потом слой)

Самая дорогая ошибка мид-PMM — реагировать на первый симптом: метрика стоит → «месседжинг не работает» → переписал → стоит → «позиционирование устарело» → пересмотрел → через три месяца всё переделано по два раза, а канал просто упёрся в потолок. Каждая переделка обнуляет накопительный эффект предыдущей версии.

**Сигнал 1 — работает, но медленнее плана** (25 триалов вместо 50, CR 9% вместо 10%). Стратегия почти никогда не виновата. Проверить: потолок канала (упёрся — добавляй второй, месседжинг не трогай) и время разгона (SEO, собственные медиа, партнёрства — 2–3 месяца; замер SEO через три недели — замер шума). Действие: объём / канал / время.

**Сигнал 2 — не работает совсем.** Диагностика по пяти слоям, **строго сверху вниз** (начнёшь снизу «переделаем лендинг» — потратишь три недели и обнаружишь, что говорил не с тем сегментом):

| Слой | Что сломано | Проверка | Действие |
|---|---|---|---|
| 1. Сегмент (М1–М2) | Разговор не с тем человеком | Сравнить пришедших с профилем секции 3 brief | Пересмотреть гипотезу сегмента, к интервью |
| 2. Позиционирование (М5) | Клиент правильный, не узнаёт ситуацию | Тест коридора: лендинг 3–5 людям из сегмента; «не уверен, что для нас» — мимо | Пересобрать позиционирование |
| 3. Месседжинг (М6–М7) | Позиция верная, формулировки не цепляют | Нормальный open + нулевой click → содержание мимо; низкий open → тема мимо | К подтверждённым формулировкам М7 |
| 4. Канал (М8) | Сообщение не доезжает | CR каналов при одном месседжинге: 5% vs 0,2% — виноват канал | Сменить канал, задачу пути сохранить |
| 5. Продукт (М3) | Приходит, пробует, уходит | Активационное действие за 7 дней < 20% | Разговор с продактом через данные (формат М11) |

**Сигнал 3 — рост оттуда, где не ждали.** Самый ценный и самый игнорируемый. Рефлекс «не по плану, фокусируемся на запланированном» стоит дорого: незапланированный рост — рынок показывает пальцем на реальный спрос. Действие: 3–5 интервью с «незваными» (кто, откуда, какая задача), 20% времени на разведку, текущий план продолжается; решение через месяц — рычаг в дереве (новый сегмент со своей VPC = запуск Tier 1 по протоколу М12) или совпадение.

## Петли роста: воронка кончается, петля — нет

Воронка линейна: каждый клиент требует нового вложения, стоимость растёт, трафик конечен. **Growth loop:** клиент использует → получает ценность → генерирует сигнал → сигнал приводит следующего; каждый оборот усиливает следующий. Воронка масштабируется бюджетом, петля — продуктом; вместе: воронка даёт стартовый поток, петля делает самоподдерживающимся.

| Петля | Механика | Что усиливает PMM | Условие |
|---|---|---|---|
| Виральная | Результат виден другим → приходят | Точки видимости (отчёт наружу несёт имя продукта), рефералка М8, бесплатный инструмент-витрина | Результат виден снаружи |
| Контентная | Опыт → кейс/отзыв/пост → приводит похожих | Процесс: через 3 мес после подписки — интервью 15 мин с CS → кейс → сайт, продажи, письма | Есть ≥10 довольных клиентов |
| Data-driven | Продукт копит данные → данные = аргумент | Три упаковки: агрегат для маркетинга (proof, растущий с базой); данные триала продавцу («за месяц сэкономили 40 часов»); данные клиента для expansion | Продукт копит метрики, ценные клиенту |

Выбор — два вопроса: результат виден снаружи? → виральная возможна. Продукт копит ценные данные? → data-driven. Контентная работает почти у всех. Кейсы М9–М10 перестают быть разовыми артефактами: налаженный сбор превращает каждого успешного клиента в контент.

## Expansion: клиент, который уже достал карту

Новый клиент в 5–7 раз дороже расширения существующего. Существующий уже внутри категории: онбординг пройден, позиционирование объяснять поздно, battle card не нужна — другой жанр разговора.

| Механизм | Триггер | Сообщение | Роль PMM |
|---|---|---|---|
| Upsell | Упёрся в лимит тарифа | Проблему не объяснять — показать, что решение = следующий шаг внутри продукта | Определить триггеры апгрейда из данных с продактом; материалы ценности следующего тарифа |
| Cross-sell | Решил одну задачу, увидел смежную | Логика capability → feature → benefit из М6, вход другой: «X решена, следующая логичная — Y» | Карта расширения: в каком порядке наращивают использование, какое сообщение на каждом переходе |
| Advocacy | Высокая активность + ощутимый результат | По lifecycle: 3 мес — интервью для кейса, 6 — рефералка, год — выступление | Процесс и частота: раз в квартал максимум; рекламный канал из лояльного клиента делать нельзя |

**Триггеры в продуктовых данных:** близко к лимиту (шестой сотрудник при тарифе на семь) → персональное касание через 1–2 недели; один модуль активен ежедневно, второй не открыт → cross-sell на задаче клиента; активность + измеримый результат (60 часов экономии) → запрос интервью для кейса (вход контентной петли); падение активности (заходил ежедневно, пропал на две недели) → churn-сигнал, реактивационная цепочка на базе нурчеринга М8. Нет аналитики — ручной режим: раз в месяц список с customer success.

## Lifecycle: шесть состояний одного клиента

| Состояние | Коммуникация | KPI |
|---|---|---|
| 1. Триал | Онбординг-серия М8: первое письмо сразу, одно действие («подключите первый источник, 10 минут до результата»); без «добро пожаловать в наш замечательный продукт» | Доля активационного действия за 7 дней |
| 2. Активация | Серия «что ещё можно»: по одной функции за раз, с привязкой к задаче М1 | Глубина использования за месяц |
| 3. Привычка | Лёгкая, без давления: образовательный контент раз в 2–3 недели; реже, чем кажется правильным, обычно лучше | DAU/WAU, NPS |
| 4. Expansion | Точечная, от данных; массовая рассылка «купите побольше» не работает | Expansion revenue, доля на 2+ модуле |
| 5. Advocacy | Кейс, рефералка, выступление; раз в квартал максимум | Рефералы, кейсы, промоутеры NPS |
| 6. Risk/churn | Реактивация: письмо к следующему пиковому сезону с напоминанием о результате, который клиент уже получал | Churn rate, доля возвратов |

Связь с деревом: дерево — вертикаль (цель → метрика → рычаг), lifecycle — горизонталь: один клиент проходит через все направления (1–2 = новые, 3 = удержание, 4 = расширение, 5 = снова новые через рефералов, 6 = удержание с обратным знаком). Lifecycle-карта — горизонтальный срез дерева. Задача PMM — видеть, где сколько клиентов и где теряется больше всего (это вход следующего рычага).

## Ритм пересмотра

| Частота | Что | Решения | Время |
|---|---|---|---|
| Еженедельно | Leading из дерева | Никаких — замер; резкое изменение → слои | 15 мин |
| Ежемесячно | Рычаги и каналы, журнал сигналов М4, обратная связь продаж | Тактические: бюджет, секция battle card, письмо | 1–2 часа |
| Ежеквартально | Дерево и brief: рычаги на цель, обратный счёт бьётся, есть ли сигнал 3 для превращения в рычаг | Добавить/убить рычаг, сместить направление, Tier 2 | Полдня |
| Раз в полгода-год | Позиционирование М5, сегменты М1–М2, ландшафт М4 | Пересмотр категории/сегмента, перезапуск позиционирования = Tier 1 | Глубокий |

Еженедельный замер — только замер, выводы в ежемесячном. Полная пересборка — только на полугодовом и только по данным.

## Типовые ошибки М13
1. Реакция на первый симптом без определения типа сигнала
2. Слои снизу вверх («переделаем лендинг»)
3. Замер накопительного канала через три недели
4. Сигнал 3 проигнорирован («не по плану»)
5. Разведка съела основной план (вместо 20% времени)
6. Переделки «на всякий случай», обнуляющие накопительный эффект
7. Рефералка «у всех же есть» без ответа на два вопроса
8. Массовая рассылка «купите побольше» вместо точечного expansion
9. Advocacy чаще раза в квартал — лояльный клиент как рекламный канал
10. Пересмотры по ощущениям без ритма в календаре

## Гейты
- Разбор сигналов требует секции 8 brief (порог) и данных ≥4 недель
- Петли и expansion — при первых платящих клиентах
- Диагностика по слоям — строго сверху вниз, одно адресное действие

## Финал курса
Инструментов много (VPC, путь, канвас, дерево, brief, петли); сильным PMM делает способность видеть связи: задача М1 → рычаг М11; точка слома М3 → момент upsell; категория М5 → expansion через год. Забыть название третьей секции battle card — ничего; увидеть, что план не бьётся, и понять, на каком слое искать, — курс сработал.
