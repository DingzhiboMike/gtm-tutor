# Инструмент разбора: канвас VP (+ шаблон Мура, питчи, разбор на 8 элементов)

Грузи при разборе любого артефакта М6. Рубрика — единственный источник вердикта. Полный текст, ❌/✅ и тетрадь — `modules/m6-messaging.md`.

## Место в нити
**Вход:** заполненный Dunford (М5) — гейт: без него VP из головы; матрица М4 — фильтр capability. **Выход:** валидация канваса (М7); тексты каналов (М8); battle card «why we win» (М9); hero → первый экран и питчи.

## Рубрика: канвас — hero + 3 VP (🔴)

| Поле | Проверка | Типовая ошибка | Наводящий вопрос | Эталон |
|---|---|---|---|---|
| Hero | Категория + главная capability + главная выгода; за 5 секунд понятно «что это, что делает, зачем» | Слоган («революционная платформа...») — подходит чему угодно | Прочитай hero глазами клиента: в какую папку он положит продукт? Что продукт делает? | «Управленческая отчётность для финдиров без ручной сборки. Собирает отчёт из ваших систем и сверяет расхождения до аудитора — закрываете квартал текущей командой» |
| Левая колонка VP | Конкретная слабость альтернативы из элемента 1 Dunford | «Неэффективные процессы», «много рутины» | Какая альтернатива и что в ней конкретно ломается? Цифры, сроки, последствия? | «Сборка вручную из пяти систем, 4 дня, на росте объёма не укладывается в срок» |
| Capability | Действие продукта для клиента — не кнопка и не результат (различение «capability ≠ фича ≠ benefit» в thinking.md) | Подменена фичей («AI-движок») или выгодой («автоматизация», «умное управление») | Закончи фразу «продукт ___ для клиента» глаголом действия. Это то, что видно на демо? | «Автоматически собирает квартальный отчёт из подключённых источников» |
| Feature | Конкретная функция-доказательство capability | Пропущена или «облачная платформа» | Какая кнопка/модуль/интеграция это обеспечивает? | «Коннекторы к 1С + модуль автосборки» |
| Benefit | Бизнес-результат из элемента 3 Dunford | «Экономия времени», «масштабируйте бизнес» — у всех | Что получает финдир в деньгах, риске, масштабе? | «Закрытие за 6 часов вместо 4 дней, силами текущей команды» |
| Фильтр VP | ≤3 VP; каждая capability из зоны «уникален» матрицы; короткий мост до выгоды | 5–6 VP; capability, которая есть у всех; честный разрыв в VP | Это есть только у вас? Клиент слышит и сам говорит «о, это мне нужно»? | 3 VP, каждый закрывает конкретную альтернативу |
| Разные сегменты | Если сегментов >1 — порядок и акценты VP перестроены, hero общий | Один текст «для всех» | У кого из сегментов болит скорость, у кого корректность? Что впереди для каждого? | «Рост» — скорость первой; «аудит» — корректность первой |

## Рубрика: утверждение Мура (🔵) — тест связности, клиент не читает

| Точка | Проверка | Наводящий вопрос |
|---|---|---|
| «Для [клиент]» | = персона + тип компании, не сполз в рынок | В канвасе «финдиры 3+ юрлица», а тут «финансовые компании» — где потерялся фокус? |
| «Который [потребность]» | Контекст + проблема, не «хотят эффективнее» | В какой момент и на чём он упирается? |
| Категория + выгода | Стыкуются логически | От этой папки ждут этой выгоды? («бухгалтерский SaaS» + «без найма» — нет) |
| «В отличие от... наш продукт...» | Альтернатива конкретная; отличие = capability | «Мы лучше» — чем именно, действием продукта? |

Собирается из канваса легко → канвас в порядке; застреваешь → размытый элемент. Вторая работа — выравнивание: продавец, маркетолог, продакт согласны с каждым словом.

## Рубрика: питчи (🔵)
30 сек = hero; тест: человек вне проекта через 30 секунд отвечает «что это за продукт» — переспросил → назвать непонятную часть (категория/capability/выгода). 3 мин = hero → проблема → 3 VP (capability → выгода, фичи не разворачивать словами) → одно доказательство цифрой → следующий шаг. Без продаж: 30 сек → заголовок первого экрана, 3 мин → структура верхней половины сайта.

## Деградация по данным
**Dunford не заполнен:** стоп, гейт — вернуться в М5 (можно быстрым проходом по 6 вопросам, если артефакты М1–М4 есть). **Ранний продукт:** 2 VP — норма. **Нет доказательств для proof:** взять консервативную считаемую величину или не давать цифру; «за первый месяц» без данных не писать.

## Частые вердикты
- Capability подменена выгодой во всех VP → «Переделать»: различение «lead with capability», начать с того, что продукт делает.
- Hero без категории → вернуть с вопросом про папку и якорь.
- Честный разрыв из М4 в VP → убрать без обсуждения: клиент поймает на третьем вопросе демо.
- Канвас хорош, Мур не собран → «Доработать»: Мур — тест, ловящий размытость, 10 минут.
- После разбора ученик несёт «красивый рерайт» копирайтера → назвать positioning drift: содержание канваса неприкосновенно, меняется грамматика.
