# Инструмент разбора: канальная стратегия (+ контентная матрица, тест-план каналов)

Грузи при разборе любого артефакта М8. Рубрика — единственный источник вердикта. Полный текст, ❌/✅ и тетрадь — `modules/m8-channels-content.md`.

## Место в нити
**Вход:** подтверждённые VP (М7 — гейт: переформулированные на проверке, убитые не вносятся), карточка триггера (М3), сегмент-покупатель (М2). **Выход:** третье звено маршрута запуска (М12); строки стратегии → основания рычагов привлечения и активации (М11); сигналы каналов → обратно в канвас М7.

## Рубрика: канальная стратегия (🔴)

| Поле | Проверка | Типовая ошибка | Наводящий вопрос | Эталон |
|---|---|---|---|---|
| Задача | Задача коммуникационного пути (1 — поле зрения / 2 — сравнение / 3 — доказательство), не маркетинговое слово | «Привлечение», «лиды», «узнаваемость» | На каком этапе своего пути клиент встречает этот канал: ещё не сформулировал проблему, сравнивает или ищет доказательство? | «Telegram Ads → задача 1» |
| VP | Конкретный подтверждённый VP; для задачи 1 — проблема, для 2 — capability, для 3 — benefit+proof | Канал без сообщения; убитый VP в строке | Какая формулировка из проверенного канваса пойдёт в этот канал? Она подтверждена? | «VP 2, проблема: расхождение всплывает у аудитора» |
| Потолок | Число: показы Вордстата, подписчики, охват — или честное «тонкий ручеёк» | «Большой», «много», «хороший» | Сколько людей из сегмента этот канал вообще может достать? Откуда цифра? | «~400 показов/мес в Вордстате — вдолгую, не основной» |
| Приоритет | Распределён: видно, что тестируем первым, что накопительное, что вдолгую | «Высокий» у трёх каналов сразу | Если ресурс — один человек и месяц, куда идёшь первым и почему? | «1 — Telegram Ads + PLS; 2 — email, партнёрка; 3 — SEO» |
| Покрытие | Каждая из трёх задач закрыта хотя бы одним каналом; слабое звено названо | Задача 3 висит на одном уязвимом канале и это не замечено | Через что клиент получает доказательство? Что случится, если этот канал выключить? | «Задача 3 держится на email и PLS, не на рекламе» |
| Границы VP | Границы по сегментам из М7 перенесены в строки | Подтверждённый «с границей» VP льётся на всех | Для какого сегмента этот VP подтверждён? Тот ли сегмент в этом канале? | «VP1 — только в каналы сегмента "рост"» |
| Экономика | Платные каналы ≥ ~100К/мес или заменены каналами времени | Тест на 20К «посмотрим, как пойдёт» | Наберёшь ли статистику на этом бюджете? Если нет — какой канал времени вместо? | «Бюджета нет → чаты + собственный канал» |

## Рубрика: контентная матрица (🔵)
Строка = одна задача + один VP + конкретный формат (статья/кейс/разбор, не «контент») + тип канала. Задачи не смешаны в одном тексте (лендинг, открывающийся кейсом для задачи 1, — типовая поломка). Каждая задача закрыта минимум одной единицей.

## Рубрика: тест-план (🔵)
Эксперимент описан действием; срок 2–4 недели; критерий успеха — число, привязанное к следующему шагу воронки (лид, активация, заявка), не охват/показы; платный — от порога статистики.

## Деградация по данным
**Нет данных по потолкам:** Вордстат + рекламные кабинеты бесплатны; для чатов/каналов — подписчики руками; совсем нет — оценка от размера сегмента М2, пометка «гипотеза». **Нет отдела продаж:** прямые продажи из таблицы выпадают, PLS становится основным маршрутом; «холодное письмо» → первый экран триала / welcome-письмо. **Нет бюджета вообще:** стратегия только из каналов времени (собственные медиа, чаты, партнёрка, PLG, outbound) — это валидная стратегия, не урезанная.

## Частые вердикты
- Список каналов вместо стратегии (задачи-слова, потолки-прилагательные, все приоритеты высокие) → «Переделать» по трём колонкам: задача, VP, потолок числом.
- Неподтверждённые VP в строках → стоп, гейт: вернуться к разметке М7.
- «Все девять каналов активируем» → вопрос про пропускную способность: что тестируем первым тремя и по какому критерию.
- Рычаг ученика (из М11) стоит на канале с пометкой «потолок исчерпан» → назвать: рычаг на выдохшемся канале не тянет, сколько ни лей.
